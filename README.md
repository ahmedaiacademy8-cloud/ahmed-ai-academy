# Ahmed AI Academic

منصة تعليمية عربية للذكاء الاصطناعي وهندسة البرومبت — موقع static بالكامل (بدون Backend)، مبني بـ HTML/CSS/JavaScript خام، جاهز للنشر على GitHub Pages أو أي استضافة static (Netlify، Vercel، إلخ).

**الموقع المباشر:** `https://ahmedmohmedabdullah.github.io/ahmed-ai-academy/`

---

## نظرة عامة

المشروع مكوّن من صفحتين رئيسيتين بهوية بصرية موحّدة (ذهبي + أزرق على خلفية obsidian غامقة، خط Cairo للعناوين وIBM Plex Sans Arabic للنصوص، RTL بالكامل):

| الصفحة | الوصف |
|---|---|
| `index.html` | صفحة الهبوط التسويقية — الكورسات، 38 خدمة AI، المسار التعليمي، الأسعار، الأسئلة الشائعة |
| `academy.html` | تطبيق SPA بـ hash router — دروس تفصيلية، أدلة أدوات، مكتبة برومبتات، بحث شامل، لوحة تقدم، شهادات |

## التشغيل محليًا

`academy.html` يحمّل بيانات `data/*.json` عبر `fetch()`، وده معناه **لازم يتفتح عبر سيرفر محلي، مش بفتح الملف مباشرة (`file://`)** — المتصفح بيمنع طلبات fetch من `file://` لأسباب أمنية.

```bash
cd ahmed-ai-academy
python3 -m http.server 8000
# افتح http://localhost:8000/index.html أو http://localhost:8000/academy.html
```

أي سيرفر static تاني (`npx serve`, `live-server`, إلخ) هيشتغل بنفس الطريقة.

## النشر على GitHub Pages

1. ادفع محتوى المجلد ده لفرع `main` (أو أي فرع تختاره) في الريبو.
2. من إعدادات الريبو → Pages → اختار الفرع والمجلد الجذري (`/`).
3. الموقع هيشتغل مباشرة — كل المسارات نسبية (relative)، مفيش أي مسار يبدأ بـ `/` بيفترض إنه على الجذر، فالموقع هيشتغل صح سواء كان على `username.github.io` أو `username.github.io/repo-name/`.
4. لو غيّرت اسم الريبو أو الدومين، حدّث الروابط المطلقة (canonical, og:url, sitemap.xml, robots.txt) اللي بتشاور على `https://ahmedmohmedabdullah.github.io/ahmed-ai-academy/`.

نفس الملفات شغالة برضو على Netlify (drag-and-drop) أو أي استضافة static تانية من غير أي تعديل.

## نظام فتح الدروس المدفوعة (كود يدوي عبر واتساب)

الدفع لسه بيتم يدويًا على واتساب (مفيش بوابة دفع ولا Backend). بعد ما الطالب يدفع:

1. افتح `data/access/access-codes.json`.
2. ضيف عنصر جديد فيه كود فريد للطالب ده + `unlocks`: قائمة فيها `id` بتاع الدرس/الدروس اللي دفع فيها (لازم يطابق حقل `id` في `data/lessons/*.json` بالظبط).
3. ابعت الكود للطالب على واتساب.
4. الطالب يكتب الكود في صفحة الدرس، ويتفتح على جهازه (متخزن في `localStorage`).

**لإضافة درس مدفوع حقيقي:** في ملف `data/lessons/*.json`، ضيف للدرس المطلوب:
```json
"accessType": "paid",
"paidLessonId": "اسم-فريد-للدرس-ده"
```
وحطّ نفس القيمة دي جوه `unlocks` في `access-codes.json`.

**تجربة حية:** فيه صفحة `#demo/paid-example` بتوضح الآلية شغالة، بالكود التجريبي `DEMO-1234` — امسح الكود ده من `access-codes.json` أول ما تبدأ تضيف طلاب حقيقيين.

**⚠️ تنبيه أمانة:** الكود ده احتكاك بسيط (friction) مش حماية حقيقية — الموقع static بالكامل ومفيش سيرفر يتحقق من حاجة، فأي حد يفتح "أدوات المطور" (Network tab) في المتصفح يقدر يشوف أي ملف JSON بيتنزل للموقع بغض النظر عن الكود. مناسب كمرحلة أولى بسيطة، مش كحل نهائي.

نفس المبدأ ينطبق على: التعليقات، المفضلة، لوحة التقدم، والشهادات — كلها `localStorage` على جهاز الطالب فقط، مفيش مزامنة بين الأجهزة، وموضّح ده بوضوح في واجهة كل ميزة منهم.

## تقرير المراجعة والإصلاح (Software QA Audit)

### تقييم المشروع قبل التعديل
المشروع كان في حالة جيدة هندسيًا بشكل عام — كود منظم، معلّق بوضوح، بدون أخطاء JavaScript، وJSON صالح بالكامل، ونظام حماية XSS (escapeHtml) متسق في كل مكان بيُعرض فيه محتوى للمستخدم. المشاكل الحقيقية كانت محدودة العدد لكنها مؤثرة:

- **باگ حرج بصري:** خاصية `.grad` في `css/home.css` كانت فاضية (`background-image: ;`) فكان نص العنوان الرئيسي "الذكاء الاصطناعي" في الصفحة الرئيسية بيظهر **شفاف/مختفي تمامًا**.
- **روابط واتساب مكسورة:** 4 مواضع في `router.js`/`access.js` كانت بتستخدم `https://wa.me/` من غير رقم، فمكانتش بتفتح محادثة فعلية.
- **رابط Skip-link غير فعّال:** موجود في `academy.html` لكن من غير قاعدة `:focus` تُظهره، فكان عمليًا معطّل لمستخدمي لوحة المفاتيح وقارئات الشاشة.
- **هويتان بصريتان مختلفتان:** `index.html` كان بيستخدم لوحة ألوان (تركواز + Tahoma) مختلفة تمامًا عن `academy.html` (ذهبي/أزرق + Cairo)، رغم إنهم نفس الموقع.
- **فلتر تصنيفات الخدمات غير شغّال:** التابات فوق الـ 38 خدمة كانت `<span>` بدون أي event listener.
- **تباين لون غير كافٍ:** `--text-dim-2` كان بنسبة تباين 4.02:1 على الخلفية الغامقة (أقل من حد WCAG AA وهو 4.5:1 للنص العادي).
- **صورة أكبر من اللازم:** `logo-full.png` كانت 500×500 (275KB) بينما بتتعرض على الشاشة بعرض 180px بس.
- **لا يوجد canonical/OG url/Twitter cards/structured data.**
- تحميل خطوط Google Fonts عبر `@import` جوّه CSS (بيأخّر أول رسم للصفحة) بدل `<link>` في `<head>`.

### تقييم المشروع بعد التعديل
كل النقاط أعلاه اتصلحت. الموقع دلوقتي: هوية بصرية موحّدة بين الصفحتين، كل الروابط شغّالة، فلتر الخدمات فعّال، تباين ألوان متوافق مع WCAG AA للنصوص الأساسية، SEO كامل (canonical + Open Graph + Twitter Card + JSON-LD structured data) في الصفحتين، تحميل خطوط أسرع، وصورة الشعار الرئيسية أصغر بـ ~43% بدون فقدان جودة ملحوظة.

### هل المشروع جاهز للإنتاج (Production)؟
**نعم**، بالنسبة لموقع static تسويقي/تعليمي بدون بوابة دفع حقيقية. النظام الحالي (localStorage للتقدم/المفضلة/الشهادات/التعليقات، كود يدوي للفتح المدفوع) موضّح بوضوح للمستخدم في كل مكان بيظهر فيه، وده اختيار معماري صريح مش نقص — مفيش خداع للمستخدم.

### هل المشروع جاهز للنشر على GitHub Pages؟
**نعم.** كل المسارات نسبية، كل ملفات JSON والصور والـ CSS/JS بتتحمّل صح، لا يوجد مسار مطلق بيفترض جذر مختلف، وتم التحقق برمجيًا من: توازن وسوم HTML، صلاحية كل ملفات JSON، صحة syntax كل ملفات JS، ووجود كل الملفات اللي بتتشار إليها بمسارات نسبية.

### مشاكل متبقية (اختيارية، مش عائق للنشر)
- **لا يوجد backend حقيقي بعد** — التقدم/المفضلة/الشهادات/التعليقات/الفتح المدفوع كلهم localStorage على جهاز واحد. ده موضّح للمستخدم بوضوح في كل مكان، لكنه قيد معماري حقيقي لو الهدف مستقبلًا مزامنة بين الأجهزة أو تحقق شهادات حقيقي.
- **الدروس/الأدوات/البرومبتات مش indexed منفردة في `sitemap.xml`** لأنها كلها routes خلف hash router (`#lesson/...`) مش URLs حقيقية قابلة للفهرسة من محركات البحث حاليًا — ده قرار موثّق مسبقًا في `sitemap.xml` نفسه، وحله الحقيقي (prerendering أو per-lesson URLs) محتاج تغيير معماري أكبر من نطاق هذه المراجعة.
